## 1. 产品定位与目标

产品提供可定制的数字人女友陪伴体验。用户选择或创建角色，为其设置形象、人设、声音和知识资料，通过实时语音与文字交流，并用预置按钮或自然语言驱动动作。角色可利用长期记忆延续之前的交流。

用户在 App 中输入自己的 Vidu API Key，由自己的 Vidu 账号承担云端调用费用。App 直接调用 Vidu，首版无需自建业务后端、登录系统、数据库服务器或 GPU 推理服务。

首版目标：

1. 在 Android 和 iPhone 上完成可连续听说、能看数字人画面的前台通话。
2. 用户能自行创建角色，设置人设、选择音色、绑定知识库。
3. 用户能输入动作描述，并将常用动作收藏为按钮。
4. 本地聊天历史与云端长期记忆能按角色管理，支持再次进入同一角色延续交流。
5. 进入角色页不自动创建实时会话；用户能清楚识别预览、连接中、通话中和结束状态。

## 2. 需求决策与边界

### 2.1 已确认的方向

| 编号 | 决策 |
| --- | --- |
| D-01 | 同时支持 Android 和 iOS，主要面向中国大陆 |
| D-02 | 使用 Vidu S2-Avatar 实时版，不沿用当前项目的组件版语音链路 |
| D-03 | 提供女友角色选择、音色选择、动作定制和语音陪伴 |
| D-04 | 用户可以输入自己的动作描述，不限于运营配置的按钮 |
| D-05 | Key 由用户本人输入，App 直连 Vidu，不自建业务后端 |
| D-06 | 角色创建、人设、音色、知识库及记忆均纳入产品设计 |
| D-07 | 底部仅“首页”“我的”两个 Tab；首页承载数字人创建与使用，我的仅承载账号、历史和设置 |
| D-08 | 状态与依赖注入采用 Riverpod，本地业务数据采用 Drift + SQLite |
| D-09 | 首版界面支持简体中文与英文，默认跟随系统，并提供手动语言选择 |

### 2.2 首版技术与体验基线

| 项目 | 首版基线 |
| --- | --- |
| App 框架 | Flutter + Dart |
| RTC | 采用 Agora Flutter SDK（iOS 使用 SPM），创建会话显式传 `rtc.provider=agora`；发布前确认账号可用 |
| 默认语音模型 | 建议 `qwen_omni`，同时满足国内语音与文字聊天需求 |
| 媒体模式 | `call_mode=video`、720p，默认只上传用户麦克风，不打开用户摄像头 |
| 角色与聊天原文 | 本地保存 |
| 知识库与长期记忆 | 使用 Vidu 托管能力，由 App 管理引用和调用 |
| 云端录音录像 | 首版默认关闭，首版不提供整场录制功能 |

Vidu 默认 RTC 就是阿里 ARTC，不存在第三个独立的“默认通道”。按用户 2026-11-09 的调整采用 Agora，其 Flutter 插件支持 SPM。ARTC 的原生桥接不属于首版必需工作；不能在未集成对应 SDK 时自动退回 ARTC。

### 2.3 首版不包含的范围

首版不做直播弹幕、礼物、点歌、OBS 推流、主播后台、自动录播下载；不做角色社区、角色交易、订阅收费、统一代付、云端账号同步和自动跨设备同步；不承诺锁屏或后台持续通话、用户摄像头视觉理解、精确骨骼动画和任意复杂动作。

这些边界用于限定交付范围，后续版本可按实际需求扩展。

## 6. 核心用户流程

### 6.1 首次使用

打开 App → 查看功能说明 → 输入自己的 Vidu Key → 选择保存方式 → 生成本地稳定 profile ID → 创建角色或从模板开始 → 配置形象与声音 → 开始首次通话。

允许暂不输入 Key 浏览官方形象、性格模板和编辑草稿；调用云端资产或开始通话前再提示配置。不能为了校验 Key 自动创建收费 live。

### 6.2 创建与使用角色

新建本地角色草稿 → 选择单人图片 → 创建 Vidu 形象资产 → 填写人设与开场白 → 选择兼容音色 → 可选知识库 → 保存本地角色 → 点击开始通话 → 创建 live → 初始化控制连接和 RTC → 显示数字人并开始交流。

“保存角色”与“开始实时通话”是不同操作。前者保存配置，后者创建实时会话。云端资产操作如有平台费用，不能统一宣传为免费。

### 6.3 自定义动作

通话页打开动作面板 → 点击预置动作或输入描述 → App 检查当前连接与重复提交 → 向当前 live 发送动作 → 显示“指令已发送” → 用户通过画面观察效果 → 可收藏该描述。

### 6.4 知识与记忆

编辑角色知识资料 → 新建或选择知识库 → 导入可访问文档 URL → 确认文档处理结果 → 保存绑定 → 下次创建通话时启用知识检索。

通话开启长期记忆 → 平台从已完成对话中提炼信息 → 下次使用同一 profile 与角色创建通话 → 按相关话题检索旧记忆。

### 6.5 结束与恢复

用户结束或 App 按策略结束 → 发送挂断并释放连接 → 查询平台会话状态 → 归档字幕、结束原因与用量。未确认结束的记录保留待核对标记，下次启动继续查询，不能仅因本地视频停止就宣称平台已停止计费。

## 7. Key、本地身份与设置需求

| 编号 | 需求与规则 | 验收要点 |
| --- | --- | --- |
| KEY-01 | 用户手动输入 Vidu Key，支持粘贴、显隐、去除首尾空白 | 不预置共享真实 Key；不在日志和普通数据文件中输出 Key |
| KEY-02 | 可选择仅本次使用或保存到系统安全存储 | 未保存时重启需重新输入；保存时可再次读取 |
| KEY-03 | 提供不创建 live 的连接检查；读取一页形象列表确认接口鉴权 | 区分未填写、网络失败、401/403；不将鉴权通过显示为“余额正常”或“RTC 已开通” |
| KEY-04 | 修改 Key 前先处理当前通话，云端资源记录关联原配置 | 不用新 Key 结束不属于该配置的旧 live |
| KEY-05 | 清除 Key 只清除凭证，不隐式删除云端资产或记忆 | 页面清楚呈现删除范围 |
| ID-01 | 首次使用生成并持久化稳定 profile ID | 重启不变；每次通话不重新随机生成 |
| ID-02 | 每个角色有独立且稳定的 character ID | 更换照片、音色或 avatar ID 不重置角色记忆分区 |
| ID-03 | 不同凭证配置默认隔离本地云端资源引用 | 同账号更换 Key 需通过显式恢复原配置处理，不能只按 Key 文本推定账户身份 |

连接检查使用 `GET /live/v1/avatars?pager.page=0&pager.pagesz=1`，成功返回空列表同样视为该接口鉴权通过；403 表示当前请求无权限，需要与无效 Key 分别处理。只读鉴权成功不代表声网通道已开通、账号有足够积分或所有资源都可用。

## 8. 角色与形象需求

### 8.1 角色字段

| 字段 | 要求 |
| --- | --- |
| 角色名 | 必填；建议产品限制 1～30 字符 |
| 头像与原图 | 保存 App 私有目录副本，保留可重新上传的源图 |
| 角色简介 | 可选；用于首页和详情展示 |
| 提示词 | 必填多行文本，描述性格、身份、背景、关系与说话方式，作为完整 persona；模板可填入后修改，不强制重复填写结构化字段 |
| 开场提示 | 可选，遵守平台 ≤ 200 字符限制 |
| 动作风格 | 可选，创建会话时传入 |
| 语音模型与音色 | 必须兼容；不能保存无效组合为可通话状态 |
| 知识库 | 可选；首版每角色绑定一个库，可复用已有库 |
| 长期记忆开关 | 按角色设置；首次启用时说明保存到 Vidu 云端 |

产品中的姓名、用户原始提示词与必要应用上下文如何拼成 persona，需要可预测的模板；用户输入原文单独保留。人设上限遵循平台当前文档的 5 万字，客户端应在发送前校验，不能通过截断悄悄丢失用户设置。

### 8.2 形象生命周期

| 编号 | 需求 |
| --- | --- |
| CHAR-01 | 提供三套性格模板作为建议初始内容，用户可修改；正式形象素材需自行准备 |
| CHAR-02 | 支持从相册选择单人图片，校验格式、压缩大小；不要求打开用户摄像头 |
| CHAR-03 | 创建形象后显示处理中、成功或失败，查询状态，不将创建响应等同就绪 |
| CHAR-04 | 无网络或资产创建失败时保留本地草稿，支持重新提交 |
| CHAR-05 | 完整角色配置保存在本地；云端 avatar 只代表形象资产，不代替完整角色 |
| CHAR-06 | 支持角色复制；复制后使用新的 character ID，默认不继承原角色记忆 |
| CHAR-07 | 删除本地角色时明确保留或另行删除云端资源；不默认级联删除共享知识库 |
| CHAR-08 | 平台图片有 90 天保留期。资产失效后允许重建，并保持原 character ID 与记忆分区 |
| CHAR-09 | 支持从 Vidu 官网官方形象目录选择，也支持自建照片；选用后生成独立本地角色，网站角色 ID 与 API avatar ID 分开管理 |

引用同一云端资产的多个本地角色应有引用检查。删除云端资源前提示相关本地角色可能受影响；删除完成后更新本地状态。

### 8.3 修改生效规则

未通话时编辑并保存，下一次通话使用新配置。通话内首版允许通过独立声音面板切换同供应商音色。完整人设编辑、角色切换和知识库绑定变化，首版在下一场通话生效；不为这些变化自动创建新 live。

虽然平台明确支持通过 session_update 热更新 persona，首版可以保留适配能力，不必在通话页增加完整人设编辑器。

## 9. 音色需求

| 编号 | 需求与规则 | 验收要点 |
| --- | --- | --- |
| VOICE-01 | 预置音色目录按 provider 分类，首版默认 qwen_omni | 不将豆包音色提交到 qwen 会话 |
| VOICE-02 | 展示音色名称、风格、可用试听状态 | 可选择无试听音色，不显示失效播放按钮 |
| VOICE-03 | 查询并展示当前账号已有克隆音色 | `GET /live/v1/voices` 不被当作完整预置目录接口 |
| VOICE-04 | 同供应商通话内切音色，等待 session_update_ack | 失败不更新当前生效音色；保存选择与生效状态分别记录 |
| VOICE-05 | 播报中切换音色，提示在当前回复结束后生效 | 不承诺中途改变已生成音频 |
| VOICE-06 | 通话创建后不更换 voice_model.provider | 更换供应商必须结束当前通话并由用户重新开始 |

首版试听使用可用、允许使用的预置或缓存素材，播放试听不创建实时会话；没有对应素材则显示音色描述。App 内音色克隆为 P1，接入时再处理参考音频、费用与状态。

## 10. 实时通话需求

### 10.1 入口与画面

| 编号 | 需求 |
| --- | --- |
| CALL-01 | 点击“开始实时通话”才创建 live；返回首页或看预览不创建 |
| CALL-02 | 创建前校验 Key、图片资产、persona、音色与所需权限 |
| CALL-03 | 首次通话说明费用来自用户的 Vidu 账号，连接准备就绪后开始计费 |
| CALL-04 | 数字人画面优先占据通话页主要空间，字幕与按钮不遮挡主要面部 |
| CALL-05 | 首版每台设备只允许一个活动通话，重复点击复用当前创建任务 |
| CALL-06 | 进入其他页面时保持通话状态入口；主动离开通话需能够明确结束 |
| CALL-07 | 无视频首帧时保留连接状态与结束按钮，不用旧循环视频冒充实时画面 |

### 10.2 音频与交互

| 编号 | 需求 |
| --- | --- |
| CALL-08 | 实时发布麦克风，接收数字人音频；不以录音结束后上传代替实时对话 |
| CALL-09 | 提供静音，静音不等同结束会话，也不承诺停止计费 |
| CALL-10 | 支持扬声器、听筒及已连接蓝牙设备，使用可用系统路由 |
| CALL-11 | 提供打断按钮，并验证 VAD 自动打断；自动打断采用何种模式由真机效果确定 |
| CALL-12 | 显示用户与数字人的实时转写，按角色与通话保存本地记录 |
| CALL-13 | 一轮文字/语音回复未完成时保持一致的输出状态，避免字幕重复或跨通话混入 |
| CALL-14 | 系统来电、音频焦点丢失、耳机插拔和蓝牙切换需更新 UI 与媒体状态 |

### 10.3 通话状态

| 状态 | 展示与可用操作 | 状态依据 |
| --- | --- | --- |
| 待开始 | 角色预览、开始按钮 | 无活动 live |
| 创建中 | 正在连接、可取消 | 创建请求仅执行一次 |
| 初始化中 | 正在准备、可结束 | 已获得 live ID，等待控制链路与媒体 |
| 通话中 | 视频、字幕、完整控制 | 控制就绪，RTC 入会与订阅状态满足交互条件 |
| 恢复中 | 连接中断提示、可结束 | 当前 live 尚可恢复；不自动创建新 live |
| 结束中 | 正在结束、停止接收新指令 | 已请求挂断、正在释放和核对 |
| 已结束 | 通话记录、用量、再次开始 | 平台结束状态已确认 |
| 结束待核对 | 本地已退出、状态待确认、可重查 | 网络等原因无法确认平台 ended |
| 失败 | 可理解原因与对应处理入口 | 资源、鉴权、账号通道、连接或权限失败 |

Vidu 控制就绪与 RTC 媒体就绪分别记录。官方计费起点是 conn_init_ack success，不把手机第一帧时间作为平台计费起点。

### 10.4 时长与生命周期

建议默认单次上限为 10 分钟，允许选择 5 / 10 / 30 / 60 / 120 分钟，平台最大值为 7200 秒。默认每 5 分钟做一次轻量时长提醒，不中断对话。这些是可在接入验证后调整的产品默认值。

建议空闲自动结束设为 300 秒，允许用户在设置中调整到平台支持范围内。静默陪伴与客户端失联分别处理；需要实测平台“无输入”如何判定，不能仅靠控制心跳推定用户仍在互动。

首版进入后台或锁屏时主动结束通话；在可用生命周期回调中执行挂断和清理。系统强杀无法保证最后一条挂断送达，应保存待核对 live，并验证平台断线回收行为。取消连接时，如果稍后仍收到创建成功响应，必须继续处理该 live 的结束，不能丢弃响应后留下孤立会话。

## 11. 文字、字幕与动作需求

### 11.1 文字与字幕

| 编号 | 需求 |
| --- | --- |
| CHAT-01 | 通话页提供“聊天”和“动作”明确入口，不通过隐藏规则混用输入含义 |
| CHAT-02 | 默认 qwen 模式可发送文字聊天；建议单条 1～1000 字符，属于产品限制 |
| CHAT-03 | 通过 type 102 发送只聊天内容；需要文本与动作联动时再使用平台对应能力 |
| CHAT-04 | 展示发送中、已发送、失败；无平台成功回执时不伪造“已读” |
| CHAT-05 | 转写内容可能分片、修订；按平台消息标识及分片语义处理，不能盲目逐帧追加重复文本 |
| CHAT-06 | 尚未收到用户转写、播报转写或最终字幕时显示对应等待状态，不生成假对话 |

独立文本聊天若使用当前实时 live，仍属于实时会话计费。首版不承诺无 live 的独立文字聊天接口；用户未通话时输入文字，需要明确进入实时互动后再发送。

### 11.2 动作

| 编号 | 需求 |
| --- | --- |
| ACT-01 | 每套初始模板建议提供 8～12 个已验证动作，如微笑、点头、挥手等 |
| ACT-02 | 允许用户输入自然语言动作；建议产品输入限制 1～200 字符，不冒充平台通用上限 |
| ACT-03 | 收藏记录包含显示名、动作描述、排序、适用角色和来源 |
| ACT-04 | 支持新增、编辑、删除、排序，通话外只保存，不创建 live |
| ACT-05 | 输入动作通过 type 101 发送，不产生普通对话回复，不主动打断当前回复 |
| ACT-06 | 客户端防重复提交，并限制连续触发积压；建议起始间隔 2 秒、待发队列最多 3 条，按实测调整 |
| ACT-07 | 没有成功回执时只显示“指令已发送”；收到错误则反馈失败，不自动反复重发 |
| ACT-08 | 复杂动作效果不确定，预置动作必须按角色实测，用户自定义动作不承诺精确姿态或固定完成时间 |
| ACT-09 | 未通话时点击动作，引导进入实时互动；预览素材与实时生成的状态区分清楚 |

语音动作匹配可启用 `action.enabled=true`，初期使用默认库 `0` 或用户已有的兼容库。直接 text_action、语音匹配动作与静默小动作是三种不同入口，不能互相冒充。

静默小动作首版使用平台默认或少量已验证配置，创建 live 时写入；不提供会话内热更新开关假象。自定义静默动作上限遵循平台当前的 50 条。

## 12. 知识库需求

| 编号 | 需求与规则 | 验收要点 |
| --- | --- | --- |
| KB-01 | 列出当前凭证可访问的知识库，支持新建并保存 ID | 不跨凭证配置引用资源 |
| KB-02 | 每角色可绑定一个知识库，也可不绑定 | 未绑定时省略或关闭 knowledge_retrieval |
| KB-03 | 首版支持平台可访问的文档 URL 导入 | 不能直接提交 `file://` 或手机沙盒路径 |
| KB-04 | 展示文档名称、处理状态、错误与重试入口 | 处理完成后才标记可用，不把已选文件视为已导入 |
| KB-05 | 支持知识库和文档查询、删除 | 删除共享库前检查本地引用并提示影响 |
| KB-06 | 角色知识库绑定变更在下一场通话生效 | 不假定托管知识库 ID 可热更新 |
| KB-07 | 文档失败、空库或检索失败可继续无该知识的会话 | 不宣称角色已经掌握失败导入的资料 |

知识库主要存详细背景故事、长资料和世界观；姓名、性格、语气、关系等必须参与 persona。知识检索不代表每次回复都会检索，也不保证所有资料逐字被记住。

平台当前默认每账号最多 100 个库、每库 1000 个文档，App 要处理配额错误，不为每次通话创建新库。

本地文件导入列为 P1：需验证通用文件上传返回的 URI 是否被知识文档接口接受。验证前保留 URL 导入，不添加未经核实的 data URI 文档上传承诺。查询文档得到的临时签名地址不作为永久资源标识。

## 13. 长期记忆需求

| 编号 | 需求与规则 | 验收要点 |
| --- | --- | --- |
| MEM-01 | 每个角色提供“记住我们的对话”设置，使用 Vidu 托管记忆 | 开启时传 provider=vidu、enable_write=true |
| MEM-02 | 用稳定 profile ID 作为 user_id，稳定 character ID 作为 agent_id | 两次通话标识不变；不同角色分区不同 |
| MEM-03 | 平台从已完成对话中提炼记忆；聊天原文另存本地 | 记忆页与聊天页内容和用途清楚区分 |
| MEM-04 | 提供当前角色记忆列表和刷新 | 按 user_id 与 agent_id 过滤，不列出其他角色全部记忆 |
| MEM-05 | 提供清空当前角色云端记忆，需确认范围 | 不误删同用户其他角色；不虚构单条删除接口 |
| MEM-06 | 删除本地记录不自动删除云端记忆 | 两种删除入口分别说明作用 |
| MEM-07 | 关闭记忆后不启用该场检索与自动写入 | 已有云端记忆保留，除非另行清空 |
| MEM-08 | 换图或重新创建云端形象不改变 memory agent_id | 原角色可继续关联旧记忆 |

同一 Vidu 账号下，恢复原 profile 与 character ID 才能尝试延续记忆。更换为另一个 Vidu 账号不能直接读取旧账号记忆。重装后未恢复本地身份时，不承诺自动找回。

云端当前没有按记忆 ID 单条修改或删除的已核实接口，首版只支持按用户/角色范围清空。需要“记住固定生日、昵称”等强约束时，用户主动设置的信息可同时保存在本地用户资料并注入人设，不只依赖自动提炼。

| 编号 | 需求 |
| --- | --- |
| DATA-01 | 按角色和通话归档聊天文本、通话时间、结束原因及平台用量 |
| DATA-02 | 区分本机记录与当前账号其他设备的云端 live；不自动接管或结束无法确认归属的会话 |
| DATA-03 | 支持删除单场或某角色本地聊天历史，删除后不宣称云端记忆已清空 |
| DATA-04 | 未获取账单时显示待更新；查询后用 billed_seconds / credits_cost 更新 |

备份包建议包含版本号、manifest 和 assets。首版备份重点保证角色与记忆身份可恢复；完整聊天历史迁移可作为后续增强。云端知识文档和记忆不因导出本地配置而变成本地全量备份，导出页要明确范围。

## 15. 费用展示与默认行为

| 项目 | 规则 |
| --- | --- |
| 付费主体 | 用户本人输入的 Key 对应 Vidu 账号 |
| 创建时机 | 只在用户开始实时通话时创建 live |
| 平台计费起点 | 按当前文档，从 on_live / conn_init_ack success 开始 |
| 费用依据 | 实际 billed_seconds、credits_cost 与平台账单 |
| 预估 | 可按当前文档费率显示估算，明确是预估且标注更新日期 |
| 静音与静默 | 不等于结束会话，不能提示免费陪伴 |
| 断线 | 保留结束状态核对，不默认停止扣费 |

当前公开费率为 1.5 积分/秒、1 积分 = 0.03125 元，单次总积分向上取整。折算 1 分钟约 2.81 元，10 分钟约 28.13 元，1 小时约 168.75 元。合同折扣、RTC 是否另结算、记忆及其他扩展费用尚未核实，不能将这些估算宣传为固定售价。

音色克隆当前文档标价 899 积分/次，客户账号前十次免费；该额度不能按每个本地 profile 重复计算。首版不接克隆创建，不在选择已有声音时触发克隆。

## 16. 异常与恢复规则

| 情况 | App 行为 | 不应发生的行为 |
| --- | --- | --- |
| Key 无效或资源无权限 | 提示检查 Key 或资源归属，保留本地角色 | 重复创建 live 试错 |
| 余额不足 | 提示去 Vidu 处理账户额度，停止本次创建 | 暗中改用其他账号 |
| 声网通道 503 | 显示当前账号通道不可用，允许稍后重试 | 未集成阿里 SDK 却自动回退 ARTC |
| 图片处理失败或过期 | 保留角色与原图，提供重建入口 | 删除人设或更换记忆 ID |
| 创建请求超时、未知 live ID | 标记结果待核对，不自动重复创建 | 按时间猜测并结束账号其他 live |
| conn_init 返回 NOT_READY | 在当前 live 上退避重试初始化 | 因 NOT_READY 新建多个 live |
| RTC 入会失败 | 结束本次 live 并保留失败原因与待核对状态 | 只关页面，不处理已创建会话 |
| 动作写出无成功回执 | 显示已发送，通过画面观察 | 无限重发或显示已完成 |
| 网络短时断开 | 对当前 live 做有界恢复，失败则结束核对 | 无限自动重建并累积费用 |
| 平台强制挂断 | 更新为结束流程，关闭输入并清理 RTC | 页面仍显示可正常通话 |
| WS close/error | 暂停新指令，按当前 live 是否可恢复进入有界恢复或结束核对 | 未核对状态就显示已恢复或另建 live |
| 字幕或记忆接口异常 | 保持媒体通话可用，单独反馈失败 | 伪造字幕或记忆内容 |
| App 被强杀 | 下次启动核对未结束记录 | 承诺强杀后一定即时停止计费 |

产品建议连接准备超时上限先设为 45 秒、短时网络恢复窗口先设为 15 秒，接入后按平台行为校准。超时策略不能代替服务器是否已成功创建的核对。

## 17. 数据与技术设计约束

### 17.1 技术栈

| 层次 | 选择 |
| --- | --- |
| 双端 UI | Flutter + Dart |
| 架构与状态 | MVVM + Riverpod；Notifier / AsyncNotifier、StreamProvider、按角色参数化的 family |
| 路由 | go_router |
| HTTP | Dio |
| WebSocket | Dart 原生 WebSocket，鉴权走 Header |
| RTC | agora_rtc_engine，使用 Vidu 返回的入会凭证 |
| Key 存储 | flutter_secure_storage；iOS Keychain、Android 基于 Keystore 的安全存储 |
| 本地持久化 | Drift + SQLite；普通设置与文件目录按用途分别管理 |
| 多语言 | Flutter 官方 flutter_localizations + intl + ARB，通过 gen-l10n 生成类型安全资源 |

当前仓库 Python 工作台不作为移动端的运行依赖。服务端密钥、自建 RTC Token 签发、OmniVoice 和本机 LLM 不加入首版链路。

### 17.2 数据实体

| 实体 | 核心字段与关系 |
| --- | --- |
| 本地资料 | profile_id、用户称呼、用户主动填写的固定资料、备份版本 |
| 凭证配置 | 本地 credential_profile_id、标签、安全存储引用；不在 SQLite 保存 Key 明文 |
| 角色 | character_id、credential_profile_id、名字、persona、开场、动作风格、原图路径、avatar_id、音色、知识库 ID、记忆开关 |
| 音色目录 | provider、voice、名称、描述、来源、试听资源状态 |
| 收藏动作 | action_id、character_id 或通用范围、名称、描述、排序 |
| 知识引用 | knowledge_base_id、文档 ID、资源归属配置、状态和本地引用 |
| 通话 | call_id、live_id、character_id、profile_id、凭证配置、RTC provider、创建/就绪/结束时间、结束确认状态、用量 |
| 消息 | local_message_id、平台消息标识、call_id、角色、文本、分片或最终状态、时间、发送状态 |

RTC Token 只在必要的会话内持有，不进入普通日志或角色导出包。云端 ID 按字符串处理。diagnostic 中记录可用于排查的 trace_id 与错误分类，不复制 Key 和入会凭证。

### 17.3 主要接口映射

| 能力 | Vidu 接口或信令 |
| --- | --- |
| 创建实时会话 | `POST /live/s_avatar/realtime` |
| 查询状态与用量 | `GET /live/v1/lives/{live_id}` |
| 控制连接 | `WSS /live/ws/live/connect` |
| 连接初始化 / 回执 | type 1 / 2 |
| 主动 / 强制挂断 | type 5 / 6 |
| 打断 | type 7 |
| 用户 / 角色转写 | 开启 transcription 后的下行 type 9 / 10 |
| 修改人设 / 音色 | type 97 / 98 |
| 文字 / 动作 / 只聊天 | type 99 / 101 / 102，按模型兼容性使用 |
| 形象管理 | `/live/v1/avatars` 与 `/{id}` |
| 自定义音色列表 | `GET /live/v1/voices` |
| 知识库与文档 | `/live/v1/knowledge-bases` 及其 documents 资源 |
| 记忆列表 / 检索 / 清空 | `/live/v1/memories/list`、`/search`、`DELETE /live/v1/memories` |

媒体必须经匹配的 RTC SDK，不能把二进制音频发送到实时版控制 WS。官方要求 15 秒内有消息维持活性，但具体支持的心跳方式需按 Demo 与实际行为验证，不自行编造 JSON 信令类型。

### 17.4 非功能需求

| 领域 | 要求 |
| --- | --- |
| 数据可靠性 | 应用重启、网络失败、资源处理中均保留草稿与稳定身份；本地数据库有版本迁移 |
| 响应与可取消 | 上传、创建、连接等操作展示进度或状态；取消后仍处理可能返回的云端资源 |
| 设备适配 | 适配安全区、刘海、系统字体放大与不同屏幕比例；不以固定像素遮挡主要按钮 |
| 无障碍基础 | 关键按钮有可读名称，状态不只依赖颜色，字幕支持字号设置 |
| 双语适配 | 中英文完整文案与错误映射；系统组件本地化；英文长文本、复数与大字号布局通过验收 |
| 网络与流量 | 图片压缩、缓存试听与预览；使用系统网络状态辅助提示，不把“有网络”当成链路可用 |
| 可维护性 | UI 不直接操作 HTTP/WS/RTC；Service、Repository、ViewModel 分层 |
| 构建 | 交付 Android 与 iOS 可安装签名构建，最低系统版本由选定 SDK 支持矩阵确定 |

## 18. 验收标准

### 18.1 功能验收

| 测试项 | 验收结果 |
| --- | --- |
| Key 与身份 | 保存/清除按设置生效；重启 profile ID 不变；检查连接不创建 live |
| 中英文 | 跟随系统、手动切换、重启保持、系统语言变更与回退正确；草稿和活动通话保持；原始内容不被覆盖 |
| 角色创建 | 创建、编辑、复制、删除可完成；角色原图、人设、音色、库引用重启后保留 |
| 云端形象 | 正确显示处理中/成功/失败；失效重建不改变角色记忆分区 |
| 双端通话 | Android、iPhone 各一台，验证只开麦克风仍可接收数字人音视频 |
| 通话控制 | 静音、音频路由、手动打断、挂断均可用；无遗留本地连接 |
| 音色 | 兼容选择正确；通话内切换得到回执并按时机生效 |
| 动作 | 预置与输入动作可发出；收藏持久化；无成功回执时不显示完成 |
| 知识 | 新建/选择、URL 导入、状态、绑定及删除流程正确；测试文档有可核对的问答结果 |
| 记忆 | 同角色跨至少三次通话验证写入和检索；另一角色与另一 profile 不混入测试记忆 |
| 删除范围 | 删除本地历史、角色与云端记忆的范围符合页面提示 |
| 后台与强杀 | 正常后台触发结束；强杀后重新启动能核对未结束记录；平台回收实测有记录 |
| 弱网与失败 | 覆盖 NOT_READY、503、欠费、断网、WS close、RTC 失败，不重复自动创建收费会话 |
| 用量 | 会话记录可与平台 billed_seconds / credits_cost 对账；未取到结果显示待更新 |
| 备份恢复 | 恢复角色与 profile/character ID；重新输入同账号 Key 后可访问原云端范围 |

### 18.2 建议性能目标

这些目标用于接入测试和后续优化，不作为当前供应商已承诺的 SLA。测试应注明设备、系统、网络、模型、SDK 版本与样本量，分别记录 Android/iOS 的 P50/P95。

| 指标 | 建议初始目标 |
| --- | --- |
| 正常网络创建到首帧 | P95 ≤ 20 秒 |
| 用户说完到首次可听回复 | P50 ≤ 2 秒，P95 ≤ 5 秒 |
| 手动打断到停止当前播放 | P95 ≤ 1 秒 |
| 简单动作发送到可见变化 | 目标 P95 ≤ 8 秒，按已验证动作人工核对 |
| 连接稳定性 | 每端至少 50 次创建/结束，记录成功率，目标 ≥ 95% |
| 连续运行 | 每端进行至少一次 30 分钟前台会话，检查音频路由、字幕与资源释放 |

若平台实测达不到上述目标，应给出实测结果、可优化部分和是否调整产品预期，不能通过模拟视频或预制音频伪装实时性能。

### 2026-11-12 用户确认的通话 UI 调整（覆盖先前界面入口说明）

通话页不再提供更多菜单及其中的手动打断、换音色、全文弹窗入口；声音在角色编辑时选择，全文在历史查看。声音按钮直接关闭/恢复远端声音的本地播放，与自己的麦克风静音独立，不再弹出音频路由选择。名称、状态与时间共用玻璃胶囊。连接页补粒子闪动/呼吸，减少动态效果时静止，底部白色圆形红 X、下方取消说明。高级设置、声音选择等底部面板去掉标题右侧关闭按钮，保留系统返回、遮罩与拖拽关闭。通话确认移除 Vidu 品牌字样，计费、时长、权限披露继续展示。


### 2026-11-12 通话交互调整（用户确认）

通话连通时在名称左侧显示呼吸绿点，减弱动态效果时静态显示；结束、失败或待核对时不显示在线绿点。通话画面取消双方实时字幕和常驻文字输入区。底部键盘按钮固定打开互动面板，不再切换动作模式；面板顶部提供比心、挥手、点头、微笑四个快捷动作（type 101），底部输入普通聊天文字（type 102）。保留现有历史文本持久化；本次取消的是通话画面字幕展示。面板随键盘上移，小屏大字号可滚动，通话结束自动关闭。快捷动作无成功回执，提示“已发送”不表示动作已完成。


### 2026-11-12 快捷动作分类扩充（用户确认）

键盘互动面板改为常用、吃喝、发型装扮、表情互动、手势姿态、道具六个分类，分类和动作各占单行并可左右滑动。默认打开常用八项；完整目录与精简映射见 QUICK_ACTIONS.md。切换分类从第一项开始，不清除聊天草稿、不发送指令。只展示纯文字动作按钮，不增加收藏或排序管理功能。普通聊天 type 102、完整动作描述 type 101 的接口、200 字限制与两秒冷却沿用现有实现。


### 2026-11-12 移除成功发送提示（用户确认）

键盘面板中的文字或快捷动作成功发送后不显示“指令已发送”等成功文案，也不占用反馈区域；保留发送失败及动作冷却的错误提示。此要求取代前文的发送成功反馈规则。
